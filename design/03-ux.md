# 03 — UX / UI Proposal

Owner: UX/UI designer. Status: proposal for the lead to merge.
Placeholders: I use **bits** as the core unit and **Stage 1 = 1939, the player as a
code-breaker**. If the economy designer picks FLOPs or entropy, swap the word; nothing
in the layout depends on it.

---

## 1. UX principles

1. **One screen, one column of attention.** No tabs, no modals, no menus to start. The page
   grows downward and sideways as systems unlock. You never have to look for anything.
2. **Plain words on controls, history in the log.** Buttons say what they do ("Decode a
   message", "Hire a clerk"). Words like "Bombe", "Enigma" and "ENIAC" live only in the log
   and in the small grey flavor line under a card title.
3. **Every card answers three questions:** what it does (plain effect, with numbers), what it
   costs, and if it is locked, *why* (inline, never hidden behind hover).
4. **The next goal is always on screen**, pinned at the top, with a progress bar. If the player
   ever asks "what now?", the design failed.
5. **Calm satisfaction.** Feedback is small and quick (under 300 ms), never blocks input, never
   pops up. Big moments (new stage) get one deliberate, skippable beat.
6. **Readable first.** Bold rather than bigger. rem units everywhere. Pure black (#000) body
   text in light mode, near-white in dark mode. WCAG AA minimum, AAA for numbers and buttons.
7. **Numbers are the hero.** The main counter is the largest, boldest thing on screen and always
   uses tabular digits so it does not jitter while ticking.
8. **The era is felt in the skin, not the layout.** Panels keep their positions across the whole
   game; only colors, fonts, borders and texture change. Muscle memory survives each stage.

## 2. Opening screen and gradual reveal

### t = 0 (nearly empty)

```
+--------------------------------------------------------------+
|                                                              |
|                                                              |
|                     0 bits                                   |
|                                                              |
|                 [ Decode a message ]                         |
|                                                              |
|          Next: decode 10 messages               0 / 10       |
|          [..............................]                    |
|                                                              |
|  ----------------------------------------------------------  |
|  1939. A hut in the English countryside. Someone hands you   |
|  a pencil and a stack of intercepted radio messages.         |
|                                                              |
+--------------------------------------------------------------+
```

Three things only: the counter, one button, the goal. The log has a single line under it.
No header, no settings gear yet (the theme toggle lives as a tiny "◐" in the top-right corner,
low-contrast until hovered; it is the only exception).

### Reveal order (Stage 1 target: ~10 min)

| # | Element appears | Trigger | Approx. time |
|---|-----------------|---------|--------------|
| 1 | Counter, "Decode a message" button, goal bar, 1-line log | Game start | 0:00 |
| 2 | Rate line under counter: "+0 per second" | First click | 0:02 |
| 3 | **Upgrades** panel (right column) with 1 card: "Sharper pencil: each click decodes 2" | 10 bits | 0:20 |
| 4 | Log grows into a real panel (scrollable, 6 lines visible) | 3rd story line | 0:45 |
| 5 | **Helpers** panel (left column): "Hire a clerk: decodes 1 per second by itself" | 30 bits | 1:15 |
| 6 | Rate line becomes live and bold: "+3.0 per second" | First helper | 1:20 |
| 7 | Locked card preview: grey card with "Needs 5 clerks" | 3 clerks owned | 2:30 |
| 8 | **Machines** row in Helpers: "Build a decoding machine: 25 per second" | 200 bits + 5 clerks | 3:30 |
| 9 | Stats strip (total, time played, best rate) collapsed under the counter | First machine | 4:00 |
| 10 | Settings link (save, export, theme, sound) in footer | 5:00 played | 5:00 |
| 11 | Stage meter (era bar at very top, see §5) | 25% of stage threshold | 6:00 |
| 12 | Stage-end project card, gold border: "Build the first electronic computer" | 75% of threshold | 8:30 |
| 13 | Stage transition | Project bought | ~10:00 |

Rules for reveal:
- New elements **fade and slide in from 0.5rem below over 250 ms**, then show a small
  "NEW" tag that disappears after the player hovers/taps it or after 20 s.
- Nothing ever moves something the player is about to click. New panels append below or to the
  side; existing buttons keep their coordinates (reserve column widths from the start via grid).
- Each reveal posts one log line ("A clerk named Joan offers to help.") so the log narrates the
  growing interface.

```
| [ Build a machine — 2,310 bits ] | | per-second rate.                      | |
|                                  | +---------------------------------------+ |
| Teams of engineers  (locked)     | +---------------------------------------+ |
| Needs 5 machines. You have 3.    | | Faster rotors        (locked)  9,000 b| |
|                                  | | Machines work 3x faster.              | |
|                                  | | Needs 10 machines. You have 3.        | |
|                                  | +---------------------------------------+ |
+----------------------------------+-------------------------------------------+
| LOG                                                                          |
| 08:02  The third machine hums to life. The clerks call it "the big one".     |
| 07:41  A captured codebook makes Tuesday's messages readable in an hour      |
|        instead of a week.                                                    |
| 07:10  You hired your twelfth clerk. The hut is running out of chairs.       |
| 06:15  ...                                                       [ all ▾ ]   |
+------------------------------------------------------------------------------+
```

Notes:
- **Card anatomy:** title (bold), plain effect (bold, black), cost (right-aligned, tabular),
  flavor (normal weight, muted, one line, optional). Effect is always a verb + number:
  "Clerks work 2x faster", never "+100% clerk efficiency".
- **Affordable cards** get a solid accent border; unaffordable a dashed border and the cost in
  muted color plus a tiny fill bar along the bottom edge showing how close you are.
- **Locked cards** show "Needs X. You have Y." inline in the card. At most 2 locked cards are
  shown at once (the nearest ones) so the panel is a menu, not a wall.
- **Bought upgrades vanish** (150 ms collapse) and post a log line. No confirmation.
  A "Bought (4)" disclosure at the bottom of the panel lists them for reference.
- **Buy multiplier** (x1 / x10 / Max) appears on Helpers only after the player owns 25 of
  anything. Keyboard: `Space` = main button, `1–9` = buy helper rows.
- Log: newest first, wraps fully, timestamps in game-time. Story lines are normal weight;
  milestone lines bold with a small era glyph. Filter chips (All / Story / Purchases) appear
  once the log passes 30 lines.

## 4. "Always a visible next goal"

A dedicated **Goal bar** sits directly under the era header, full width, sticky on scroll.

```
 NEXT GOAL:  Hire 5 clerks to unlock decoding machines
 [##########################..............]   3 / 5
```

- Exactly **one** goal at a time. It is chosen by priority: (1) the next unlock trigger the
  player is closest to, (2) the stage-end project, (3) a soft goal ("Reach 1,000 per second").
- Text is a full sentence of the form **verb + target + reward** ("…to unlock X").
- Right side shows progress numerically and, once a rate exists, an **ETA** ("~1m 40s") so the
  player can choose between waiting and clicking.
- When the goal completes: bar flashes accent color for 400 ms, text crossfades to the next
  goal, completed goal goes to the log in bold. No popup.
- The thing the goal points at gets a 2px accent outline pulse (once, not looping) so the eye
  connects goal to control.
- Secondary: the **era header bar** shows overall stage progress (the long view); the goal bar
  is the short view. Two horizons, always both visible.

## 5. Huge numbers

The game spans maybe 10^0 to 10^60+. Rules:

**Formatting ladder** (one setting, defaults to "Words"):

| Range | Words (default) | Scientific (option) |
|-------|-----------------|---------------------|
| < 1,000 | 999 | 999 |
| < 1e6 | 31,240 (full, comma groups) | 31,240 |
| 1e6 – 1e15 | 4.21 million / billion / trillion / quadrillion | 4.21e9 |
| 1e15 – 1e33 | short names up to decillion | 4.21e21 |
| > 1e33 | 4.21 × 10^45 (superscript rendering) | 4.21e45 |

- Always **3 significant digits** past 1 million, tabular figures, fixed-width counter box
  so the layout never shifts.
- **Unit grows with the era**, like the real world: bits → kilobytes → megabytes → … →
  yottabytes, shown as a secondary line under the counter: "31,240 bits  ≈ 3.9 kilobytes".
  When the number crosses a unit boundary, the log notes it.
- **Comparison line** (the human anchor), updates at thresholds, muted, under the counter:
  - "About one page of typed text" → "Enough to store a novel" → "The Library of Congress"
    → "Every word ever spoken" → "Every atom in a grain of sand."
  This turns an abstract exponent into a felt scale and doubles as a story beat.
- **Rate is shown as a multiplier of the previous stage's best rate** once in Stage 2+:
  "+4.2 billion per second (1,000,000x 1939)". This keeps requirement 4 (always faster)
  visible.
- **Stage meter on a log scale.** The era header bar fills on log10(progress), so it moves at
  a steady visual pace instead of sitting at 0% and leaping at the end.
- **Cross-game "speedometer"** (stats strip): a tiny log-scale sparkline of rate over time.
  It should be a near-straight upward line; that line *is* the game's thesis.

## 6. Feedback and feel

Principle: every action gets **one visual + optional one sound**, both under 300 ms.

| Event | Visual | Sound (off by default until first click; volume 30%) |
|-------|--------|------------------------------------------------------|
| Main click | Button depresses 1px (transform), a "+12" floats up 1.5rem and fades in 600 ms; max 5 floaters alive, then they merge into one "+60" | Era click: typewriter key (1939), relay clack (50s), keyboard tick (80s), soft tap (2000s+) |
| Counter tick | Digits update ≤ 10 times/sec; no animation on the digits themselves | none |
| Buy helper | Row background flashes accent at 20% opacity, 200 ms; owned count bumps (scale 1.1 → 1) | short low "thunk" |
| Buy upgrade | Card collapses (height → 0, 150 ms); affected row's rate number flashes green once | rising two-note chime |
| Unlock / new panel | Fade + slide in, "NEW" tag | soft single bell |
| Goal reached | Goal bar flash + crossfade | same bell, a fifth higher |
| Milestone (x10 rate, unit change) | Counter glows once (text-shadow, 500 ms), bold log line | three-note arpeggio |
| Stage complete | See §7 transition | era-specific sting, ≤ 3 s |

- Respect `prefers-reduced-motion`: floaters and slides become instant opacity changes.
- Holding the main button (or holding Space) auto-repeats at 10 clicks/s. Accessibility
  win and kills the RSI complaint; balance can treat it as "max click rate".
- Sound toggle in settings; mute icon appears beside the theme toggle after the first sound.
- Number go-up rule: never animate the counter to "count up" toward a value; show truth instantly.

## 7. Era skins (cheap: CSS variables + one class on `<body>`)

Layout is constant. Each stage sets `body.era-1939`, `body.era-1970`, etc., which only
redefines tokens. Light/dark is a second axis: each era defines both.

```css
:root            { --bg; --surface; --text; --muted; --accent; --border-style;
                   --radius; --font-ui; --font-num; --texture; --shadow; }
.era-1939        { /* paper & typewriter */ }
.era-1939.dark   { /* carbon paper: ink-blue bg, cream text */ }
```

| Stage / role | Light mode | Dark mode | Fonts (Google Fonts) | Texture / details |
|---|---|---|---|---|
| 1. 1939–45 Code-breaker | Cream paper bg, #000 text, red-ink accent | Navy carbon, cream text | Special Elite for titles only; IBM Plex Mono for numbers | Subtle paper grain (SVG noise data-URI, 4% opacity); cards look like index cards, square corners, 1px solid |
| 2. 1950–60s Mainframe | Pale green-grey, punch-card buff cards | Dark steel | IBM Plex Sans Condensed | Cards have a clipped top-left corner (punch card); dotted rule lines |
| 3. 1970–80s Terminal / PC | Beige plastic, amber accent | **Black + phosphor green/amber**, the signature look | VT323 for header only, Plex Mono body | Optional faint scanlines (repeating-linear-gradient) |
| 4. 1990s Web / Investor | White, blue links, teal accent | Dark grey with web-safe accents | Verdana-ish system sans, bold | Bevelled 2px outset buttons, grey "window" title bars on panels |
| 5. 2010–20s AI lab | Clean white, one violet accent | Near-black, soft glow | Inter | Rounded 0.75rem, generous spacing, soft shadows |
| 6. Post-human | Starts as 5, desaturates; text gradually becomes the only element | Pure black | Same as 5, letter-spacing widens | Panels lose borders; final screen is just the counter |

Rules:
- **Readability beats theme.** Display fonts (Special Elite, VT323) only on headers and the
  era name. Body text, effects and costs always use a clean bold sans or mono. Every
  palette is checked for AA contrast in both modes. Light mode text stays #000 in every era.
- **Transition** (~2.5 s, skippable by click): screen dims, a centered title card shows
  "1946 — Stage 2: The Electronic Brain. You are now: Head of the computing lab", then
  tokens swap with a 600 ms crossfade (`transition` on background/color). Panels from the
  old stage collapse into a one-line "1939 summary" row at the bottom of Helpers.
- **Role label** under the era name ("You are: Code-breaker") makes requirement 2 visible.
- Cost: ~40 lines of CSS per era, 3–4 font families total, zero images except one noise SVG.

## 8. Mobile and desktop

**Breakpoints** (rem-based): `< 40rem` phone, `40–64rem` tablet, `≥ 64rem` desktop.

Desktop (≥ 64rem): layout in §3. Two columns (Helpers | Upgrades), log full width below.
Max content width 72rem, centered. On very wide screens (≥ 100rem) the log moves to a
right-hand third column so it is readable without scrolling.

Phone:

```
+--------------------------+
| 1939 · Stage 1  [====.] ◐|
| Next: 5 clerks    3 / 5  |
| [##########......]       |
+--------------------------+
|      31,240 bits         |
|   +312.5 per second      |
|                          |
+--------------------------+
| (scrolling content)      |
| HELPERS                  |
|  Clerks 12 ... [Hire 148]|
|  Machines 3 .. [Build ..]|
| UPGRADES                 |
|  [card] [card]           |
| LOG (last 3, tap for all)|
+--------------------------+
|  [  Decode a message  ]  |  <- sticky bottom, thumb zone,
+--------------------------+     min height 3.5rem
```

- Header + goal bar sticky at top (compact, ~5rem total). **Main button sticky at the bottom**
  in the thumb zone; everything else scrolls between them.
- Single column order: Helpers, Upgrades, Log. When a new panel unlocks off-screen, a small
  "New: Upgrades ↓" chip appears above the sticky button; tapping scrolls to it.
- Touch targets ≥ 2.75rem (44px). No hover-only information: locked reasons and effects are
  printed, never tooltip-only. Disable double-tap zoom on buttons (`touch-action: manipulation`).
- Tap feedback mirrors click feedback; optional haptic (`navigator.vibrate(8)`) on purchases
  only, off with sound.
- Offline progress: on return, a single log line "While you were away: +2.1 million bits
  (3h 12m)" plus the counter catching up instantly. No modal.
- Autosave every 10 s and on `visibilitychange`; phones kill tabs aggressively.

Both:
- Theme: follows `prefers-color-scheme` by default; the ◐ toggle cycles System → Light → Dark
  and remembers the choice.
- Base font size 1rem (respects user zoom); counter 2.5rem bold, everything else 1rem or
  0.875rem, emphasis through weight (600/700) not size.
- Full keyboard play: Tab order follows visual order, visible focus ring in era accent.
- Screen readers: counter is `aria-live="off"` (too chatty); goal bar and log milestone
  lines are `aria-live="polite"`.
