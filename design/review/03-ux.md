# 03 — UX review (housekeeping, Stages 1 and 2)

Reviewer: UX designer. Angle: everything the player sees and reads.
Method: read the code and docs, then played both stages end to end in headless Chrome (light, dark, 1200 px and
390 px phone), using the dev "Start Stage 2" button too. No console errors. Contrast checked for all tokens in both eras.

Severity: **bug** (wrong behaviour) · **inconsistency** (two places disagree) · **polish** (rough for a player).
Ranked most important first. 23 findings.
Line numbers refer to commit 58cb407. While I was writing this, uncommitted edits started to cover parts of #3
(ledger order), #18 (Stage 1 title line) and #22 (D3, status line). Check those three against the working tree
before you apply them.

---

## Findings

### 1. Holding Enter on the main button clicks with no limit — bug
`src/main.js:73`. A held mouse button repeats at 6/s and a held Space is throttled to 6/s. But Enter on the focused
button fires a `click` on every key repeat, and none of them are throttled. In a test, 30 Enter repeats gave 30 clicks
in 21 ms. Keyboard players can click about 5× faster than the design allows (05 §8 cut the hold rate to 6/s because of this).
**Fix:** use the same throttle as Space:
```js
mainBtn.addEventListener('click', (e) => {
  if (e.detail !== 0) return;
  const now = performance.now();
  if (now - lastKeyClick >= 1000 / CONFIG.holdRepeatPerSec) { lastKeyClick = now; doClick(); }
});
```
(Move `let lastKeyClick = 0;` above this line.)

### 2. The whole goal bar is an aria-live region, so screen readers keep reading it — bug
`index.html:29`, `<section id="goal" aria-live="polite">`. `#goal-nums` changes several times a second
("78.7 million of 1.30 billion…"), so a screen reader keeps reading it out.
**Fix:** remove `aria-live="polite"` from `#goal`, and put it on `#goal-text` only:
`<span id="goal-text" aria-live="polite"></span>`. That text changes only when the goal changes.

### 3. The ENIAC line sits on the Stage 1 side of the ledger divider — inconsistency
`src/engine.js:308–309` and `:340`. `passLedger` logs "Philadelphia, February 1946… ENIAC…" first, and then
`enterStage` adds the divider "Stage 2 · The computing lab". The ledger shows newest first, so it reads:
opening line / **divider** / ENIAC line / Stage 1 lines. The ENIAC line (Feb 1946) ends up under Stage 1.
06 §3 says the order is divider, ENIAC line, opening line.
**Fix:** log the closing line after the divider:
```js
// passLedger
if (STAGES[s.stage + 1]) enterStage(s, s.stage + 1, st.next);
else { addLog(s, st.next.text, st.next.date, 'milestone'); s.phase = 'next'; }
// enterStage(s, n, intro)
addLog(s, st.title, null, 'stage');
if (intro) addLog(s, intro.text, intro.date, 'milestone');
checkBeats(s);
```

### 4. On "To be continued" the header drops back to the first role — bug
`src/engine.js:306`. `passLedger` clears `s.bought`, and promotions are based on upgrades you bought. So after
Stage 2 the header changes from "Director, computing division" back to "Director of a computing lab".
**Fix:** delete line 306 (`s.bought = {}; s.choices = {}; s.revealed = {};`). `enterStage` already clears all three
(line 335), so the stage-to-stage path does not change. With no next stage, the bought list stays, and the role stays too.

### 5. Very long numbers in the goal bar and on locked cards — inconsistency
`src/engine.js:166` and `:444` use `fmtInt`. The goal reads "Run **1,300,000,000** operations in total to build a
computer for the Moon", but the numbers right next to it say "of **1.30 billion** in total". Locked cards do the same
("run 12,000,000 … (5.2 million of 12.0 million)"). On a phone the goal text takes 2–3 lines.
**Fix:** `import { fmt } from './format.js';` in engine.js, and use `fmt(...)` instead of `fmtInt(...)` on both lines.
Stage 1 does not change ("650,000"). Stage 2 shows "Run 1.30 billion operations in total…".

### 6. Old ETA left on the goal bar after the goal changes: "Ready · ~9.5 s" — bug (flicker)
`src/ui.js:246–247` with `:214`. When the goal kind changes, `lastGoalText` is updated *before* `goalNums` runs, so the
"text changed" check never fires. The ETA from the old goal stays for up to 1 s. Seen on both stages:
"Ready · ~9.5 s", "Ready · ~30 s", and "Save up for "Read Berlin's orders" … · ~9.5 s" (that was the old goal's ETA).
**Fix:** add `etaAt = 0;` next to `goalKind = goal.kind;` (line 246).

### 7. "Reset game" still opens a confirm() pop-up — inconsistency (player preference, 05 D10)
`src/main.js:102–106`. The same pop-up also opens from "Start again from 1939" (`index.html:85`) on the
To be continued screen.
**Fix:** a two-step button with no pop-up. On the first press the label becomes "Press again to erase everything"
(4 s); a second press within that time resets the game:
```js
case 'reset':
  if (btn.dataset.armed) { try { localStorage.removeItem(SAVE_KEY); } catch (err) {} s = E.createState(); location.reload(); }
  else { const old = btn.textContent; btn.dataset.armed = '1'; btn.textContent = 'Press again to erase everything';
         setTimeout(() => { delete btn.dataset.armed; btn.textContent = old; }, 4000); }
  break;
```

### 8. A locked card says "Coming soon." and not why — polish (player preference: locked items say why)
`src/ui.js:170`. When the next idea's condition is already met, the card waits for one of two reasons: two ideas are
already open, or the 8 s gap or a quiet moment (`hush`) is still running. The card only says "Coming soon." You can see
this near the end of Stage 1: "Tape-reading machine · Coming soon." while two cards are open.
**Fix:** in place of `'Coming soon.'`, use
`open.length >= 2 ? 'Appears when you buy one of the ideas above.' : 'Appears in a moment.'`

### 9. Locked card counts: "(0 of 1)" and "(3 of 6 machines)" — polish
`src/ui.js:170`. A locked card that waits for an upgrade reads `Locked: buy "Chips" (0 of 1).` (this happens to
Time-sharing if you pass 88 million before you buy Chips). Count conditions repeat the noun:
"build 6 machines (3 of 6 machines)".
**Fix:** leave out the brackets when `p.kind === 'upgrade'`, and never add `unitLabel` here. The sentence already
names the thing. Result: "Locked: build 6 machines (3 of 6)." and "Locked: buy "Chips"."

### 10. "100.0 million" in prices — bug (number format)
`src/format.js:23–27`. `sig3(99.99)` takes the `>= 10` branch and returns "100.0". Seen as
"Build a computer · 100.0 million operations". The same thing at 999.95 gives "1000 million".
**Fix:** round first: `if (v >= 99.95) return v.toFixed(0); if (v >= 9.995) return v.toFixed(1); return v.toFixed(2);`
and in `fmt`, when `sig3(v)` returns "1000", move up one word (or compute `exp` from the rounded number).

### 11. At the start of Stage 2, "You have" is larger than the total, with no total line — polish
`src/ui.js:78`. The total line only shows when total > balance. At the start of Stage 2 you carry 200k–430k but have
made almost nothing since 1946. So the counter says "433,652 checks", the goal bar says "100,378 of 1.30 billion in total",
and nothing explains the gap.
**Fix:** `show($('total'), Math.abs(total - s.ops) > 0.5);` Stage 1 is unchanged. In Stage 2, "Made since 1946: 100,378"
shows from the start.

### 12. Phone: buy buttons wrap in the middle of the price — polish
`style.css` phone block (`@media (max-width: 40rem)`, line 246). At 390 px, "Build a computer · 8.11 million operations"
breaks into a 2×2 block ("Build a / computer | 8.11 million / operations").
**Fix (inside the phone block):** `.buy-btn { width: 100%; flex-wrap: wrap; gap: 0 1rem; } .buy-btn .cost { white-space: nowrap; }`
The label and the price each get their own clean line.

### 13. Phone: the theme button sits on a row of its own — polish
`style.css:92–96`. On a phone the header wraps, so ◐ drops to a third row and the goal bar is pushed down about 60 px.
**Fix:** `#era { flex-wrap: nowrap; }` and `.era-left { min-width: 0; }`. The role text wraps beside the button.

### 14. After the last stage: an empty bottom bar, and "+1.31 million per click" with no button — polish
`src/ui.js:82` and `:96–99`. In phase `next`, the fixed click bar on phones is still there (border and padding, no button).
The rate line still says "+N per click", and N is now 5% of the new legacy rate.
**Fix:** `const canClick = E.isActive(s) || s.phase === 'ending';`. Then use
`show($('click-wrap'), canClick || s.phase === 'handover');` and write the rate line as
`` `+${fmt(rate, 1)} per second` + (canClick ? `   ·   +${fmt(clickValue, 1)} per click` : '') ``.

### 15. Customer list reads "Census Bureau, Tea shops, An insurance company, A bank…" — polish
`src/data/stage2.js:47–57` (`name` fields). Mid-sentence capitals and articles read badly in
"Customers: …".
**Fix:** names `'the Census Bureau'`, `'tea shops'`, `'an insurer'`, `'a bank'`, `'an airline'`, `'universities'`,
and in `src/ui.js:423` make the first letter of the joined list a capital
("Customers: The Census Bureau, tea shops, an insurer, a bank, an airline, universities.").

### 16. The selling panel's intro says "money" twice — polish
`index.html:66`: "Customers pay money for part of your computer time. Mainframes are paid for with money."
**Fix:** "Customers pay for part of your computer time. Money buys mainframes and some ideas."
(Time-sharing is also bought with money, so "mainframes" alone is not the whole story.)

### 17. "Each checks 0.5 guesses per second. Together: 2.5 checks per second." — inconsistency
`src/ui.js:135`. Two units in one sentence in Stage 1. In Stage 2 it repeats "operations per second" twice.
**Fix:** `Together: ${fmt(out * n, 1)} per second.`

### 18. Stage 1 has no ledger title; Stage 2 does — inconsistency
`src/data/stage1.js:9` (`title: 'The Codebreakers'`, never shown) vs `stage2.js:11` (`'Stage 2 · The computing lab'`,
shown as a divider). The ledger has a heading for Stage 2 but none for Stage 1.
**Fix:** `title: 'Stage 1 · The codebreakers'`, and in `createState()` add `addLog(s, st.title, null, 'stage');`
before `checkBeats(s)` (engine.js:47). Old saves are not affected.

### 19. "Pass the ledger on" loses keyboard focus, and its scroll ignores reduced motion — polish
`src/main.js:95`. The pass button hides itself, so focus falls back to `<body>`. `scrollTo({behavior:'smooth'})`
animates even when the player has reduced motion turned on.
**Fix:**
```js
case 'pass': E.passLedger(s); save(); render(s);
  window.scrollTo({ top: 0, behavior: matchMedia('(prefers-reduced-motion: reduce)').matches ? 'auto' : 'smooth' });
  document.getElementById('main-btn').focus({ preventScroll: true }); break;
```

### 20. The theme button does not say which theme is on — polish
`index.html:25`, `src/main.js:119`. The aria-label is always "Switch theme". The `title` is only set after the first
press, so a mouse user sees no tooltip at first.
**Fix:** in `cycleTheme` and once at start-up, set
`btn.title = btn.ariaLabel = \`Theme: ${cur} (press for ${next})\``.

### 21. Promotions are not announced — polish
`src/ui.js:69`. The underline is visual only. Stage changes and the unit rename go through `#announce`, but promotions do not.
**Fix:** `if (shownRole !== null) { pulse(...); announce(\`You are now ${role}.\`); }`

## Nothing to fix
- **Contrast, both eras, light and dark.** Text is at least 14:1 (pure black #000 in light mode, both eras). Secondary
  text is at least 10:1. Accent on background, and the "Locked:" text, are at least 6.9:1. Text on goal tags is at least
  6.8:1. Dashed borders are at least 4.4:1. Nothing below WCAG AA.
- **Reduced motion** (apart from #19). The CSS removes all animations and transitions. Floaters, the goal-bar drain and
  refill, and the unit strike-through all check the setting in JS.
- **Flicker** (apart from #6). The team line, sell status and money rate are rounded and change only when you buy something.
  Card ETAs update once a second.
- **Phone width.** No horizontal scroll at 390 px. The ledger drops to one column. The click button is fixed at the bottom.
- **Sell panel controls.** It is a real button group with `aria-pressed` and an `aria-label`. Targets are 2.75 rem.
  The selected option is shown by its fill and by the attribute.
- **Legacy row.** "Bletchley Park, 1939–45 · LEGACY · 32,913 operations per second, forever." It is fixed and clear,
  and it follows the unit rename.
- **Card wording.** Effects say "X work N× faster" / "Everything works…" the same way in both stages. Choice options
  read the same way in both stages ("each one costs N% more than the last, not M%").
- Side note: the Census Bureau's ledger line no longer says "You can sell computer time now" (data edited during this
  review). That is fine, because the "Magnetic tape" card already says it unlocks selling and the panel appears at once.
