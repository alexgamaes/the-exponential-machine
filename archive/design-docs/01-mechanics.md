## Primary Action

- **Button:** `[COMPUTE]`
- **Effect:** Generates FLOPs (`flopsPerClick: 1`). Each FLOP clears 10 search states.

---

## Resources

### FLOPs (Processing Power)
- Generated by clicking COMPUTE and passively by personnel.
- Used internally by the search system — not directly spent by the player.
- Displayed as a running total (flavor) and as FLOPs/sec (passive rate from personnel).
- Also spent on some Operations (e.g. Frequency Analysis costs 1,500 FLOPs).

### Data (Universal Currency)
- Earned via **The Drop** — when a stream's search space is fully cleared.
- Capped (starts at 500 Data). Expanded by Operations and infrastructure.
- Spent on: Personnel, Infrastructure, Operations.

### Billets (Personnel Capacity) — displayed as "Supply" internally
- Hard cap on total personnel headcount.
- Starts at 12.
- Expanded by: Huts (+6 each), Canteen Expansion (+20 each), `recruitFirst50` Operation (+50).
- Coffee Rationing reduces supply cost per person by 15% per upgrade (max 3).
- Phase 0 flavor: "tea, rations, billets." The label evolves in later phases.

---

## The Search Loop

```
Click / Personnel FLOPs → Search Space Attrition → The Drop → Data
```

- Each stream has a `spaceCurrent` (state count). FLOPs chip away at it each tick.
- **The Drop**: when progress reaches `spaceCurrent`, a Data reward is paid and a new harder intercept loads.
- Drop reward scales: `rewardBase × dataPerDrop multiplier × DROP_SCALE^dropCount`.
- `DROP_SCALE = 1.08` — each Drop the space grows slightly, reward grows to match. Loop time stays roughly consistent. The exponential comes from multipliers (Operations, personnel), not from raw scaling.
- Search space starts at 300 states (Army Enigma). Design target is 3,200 — to be adjusted when early pacing is tuned.

## Initiatives (Operations)

> What Universal Paperclips calls "Projects," this game calls **Initiatives** (UI label) / Operations (internal).

- One-time executable actions. No queue — instant effect on click.
- Each Initiative is a **DAG node** with a `trigger` (when it appears), `cost`, `gates` (additional execution blockers), and `effect`.
- **Trigger system**: `refreshAvailableOperations` runs every tick. When a node's trigger conditions are satisfied, it enters the available pool. This is how the UP "upgrades appear contextually" pattern is implemented.
- Source of truth: `src/data/operations.js`. Add a node there only — no other file needs editing.

### Trigger vs Gate
| Field | Controls | Example |
|---|---|---|
| `trigger` | Visibility — when the card appears | `{ minDrops: 1 }`, `{ operations: ['x'], minJuniorCalculators: 10 }` |
| `gates` | Executability — when you can click it | `{ minBoffins: 5, minHuts: 2 }` |

## Key Implementation Notes (gaps vs design)

- **Search space base**: Currently 300 states. Design spec is 3,200. Needs tuning when early pacing is settled.
- **Billets label**: UI still shows "Supply." Rename to "Billets" for Phase 0 pending implementation.
- **Paper Roll Storage**: Mentioned in `02-phase-0.md` as a data cap upgrade — covered by `cardIndexEarly` (×5 cap) but not yet a separate purchasable item.
- **Mechanical Hand-Crank**: Click multiplier upgrade in design — not yet implemented.
- **Night Shift**: Implemented (auto-activates, ×2 FLOPs for 90s / 10min cooldown). Unlocked by `recruitFirst50`.
- **Bulk buy**: Junior Calculator bulk-buy (×10) described in design — not yet implemented.
- **Phase 1**: Not started. Full spec in `06-detailed-mechanics-p0-p1.md`.
